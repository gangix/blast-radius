# Sample outputs

These are **real Blast Radius PR comments** — generated by the agent running against
a seeded DataHub (the showcase-ecommerce dataset), not hand-written. Each is the
verdict for one proposed schema change to the `analytics.order_details` model.
No LLM decides severity; every fact (lineage, the exact breaking queries, usage,
ownership) comes from DataHub.

| File | Change | Verdict |
|---|---|---|
| [`pr-comment-1-breaking.md`](pr-comment-1-breaking.md) | drop `discount_amount` | ❌ Breaking — 2 finance queries (~11 reads/day, run by 2 people) + 3 dashboards / 12 charts |
| [`pr-comment-2-warning.md`](pr-comment-2-warning.md) | drop `warehouse_name` | ⚠️ Review — 1 query still reads it |
| [`pr-comment-3-clean-pass.md`](pr-comment-3-clean-pass.md) | drop `gift_wrap` | ✅ Safe to merge — nothing queries it |

The ✅ case is the interesting one: `order_details` feeds many dashboards, but
**no query reads `gift_wrap`**, so the bot says *ship it* instead of crying wolf.
Severity is weighted by real query usage, not raw downstream node counts.

## Write-back

On a ❌/⚠️ change (when enabled), the agent also **contributes the verdict back to
DataHub** through the Agent Context Kit — a knowledge document plus a
`blast-radius-breaking` / `blast-radius-review` tag on the affected column — so the
impact analysis lives in the catalog, not just the PR thread.
